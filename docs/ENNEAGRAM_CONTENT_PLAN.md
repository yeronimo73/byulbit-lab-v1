## 0. 한 줄 목표

63문항 도구는 유지한 채, **결과·인트로·유형 메타를 “한 장 미러 리포트” 수준으로 채워**  
사용자가 “내용이 없다”고 느끼지 않게 한다.  
임상 검사·운세 확정이 아니라 **비공식 자가탐구 거울**임을 전 구간에서 지킨다.

## 1. 현황 진단 (As-Is)

### 1.1 이미 있는 것

| 자산 | 내용 | 평가 |
|------|------|------|
| `enneagram-items.json` | 63문항 (유형당 7) · Likert 1–5 | 균형 양호 |
| `scoreEnneagram` | core · wing · tritype · 9% | 스펙 준수 |
| 결과 UI | 유형명 · summary 1줄 · 날개/트라이타입 · 막대 · 탐구 일지 | **설명이 얇음** |
| 인트로 lead | 2–3문장 | 한계·읽는 법 부족 |
| 면책 | disclaimer 1줄 | 최소 |

### 1.2 비어 보이는 이유

`enneagram-types.json` 유형 필드가 사실상 3개뿐:

- `name` · `center` · `summary`(1문장)

결과 렌더가 `coreInfo.summary`만 쓰므로, 점수가 나와도 **읽을 본문이 없다.**

### 1.3 외부 원천 (Brain) — 현실 점검

| 원천 | 양 | 품질 메모 |
|------|-----|-----------|
| `애니어그램 유형 1`~`9` 위키 | 9페이지 | **스텁 수준** (영문 한 줄 + 라벨). 그대로 복붙 불가 |
| `애니어그램 개요` · `날개` · `화살` · `트라이어드` | 구조 개념 | 구조 카피 초안에 유용 |
| `애니어그램 연구와 한계` | 있음 | **limits 블록 정본 후보** (안전 문장 포함) |
| raw clippings / papers | 60+ | Institute·Truity·PubMed 등 — **참고만**, 장문 전재 금지 |
| 홈/연구 허브 | 에니어 딥링크만 | 거울 agenda “일지 읽기”와 연결 여지 |

**결론:** “Brain에 유형 본문이 두껍다”가 아니라 **구조·한계·클리핑 풀이 있다**.  
사이트용 카피는 **별빛 톤으로 새로 써야** 한다 (클리핑은 팩트·동기 키워드 체크용).

### 1.4 비교 기준 (같은 사이트 내)

| 도구 | 결과 깊이 |
|------|-----------|
| 행성 거울 | `gift` · `shadow` · `exploreQuestions` · 천문 필드 등 **다층** |
| 별자리 | 4층 (천문·빛·거울·출처) |
| 에니어그램 | summary 1줄 ← **갭** |

에니어 보강은 행성 거울 필드 밀도에 **맞추는 것**이 목표 상한선이다 (그 이상 장문 위키 금지).

## 2. 목표 (To-Be)

### 2.1 사용자 경험

1. 시작 전: 무엇인지 · 어떻게 읽는지 · 무엇이 **아닌지** 30초 안에 이해  
2. 결과 후: core 유형을 **2분 분량**으로 읽고, 날개·트라이타입 의미를 알며, 질문 2개로 일지에 쓸 수 있음  
3. 전 구간: “진단/운명” 오해 방지 문구 노출  

### 2.2 제품 범위 (In / Out)

| In | Out |
|----|-----|
| types JSON 확장 | 공식 검사 라이선스 구매·복제 |
| 결과 UI 보강 | 문항 수 대폭 변경 (63 유지 기본) |
| 인트로·한계 블록 | 별자리↔유형 확정 대응표 |
| (선택) 9유형 정적 목록 페이지 | 결제·상담 예약 |
| bibliography 1~3건 | 화살/통합 상태 시뮬레이션 게임 |

### 2.3 성공 기준 (Acceptance)

- [ ] 9유형 모두 `summary` 외 **동기·그림자·성장질문** 필드 존재

- [ ] 인트로에 `about` + `limits` + `howToRead` 표시  
- [ ] 금지어 검수: 치유·운명·확정·임상 진단 대체 암시 0건

## 3. 정보 구조 (스키마)

### 3.1 `enneagram-types.json` 목표 형태

```json
{
  "updated": "YYYY-MM-DD",
  "about": "에니어그램이란 — 40~80자 정의",
  "howToRead": [
    "점수는 경향의 스냅샷이다",
    "core·날개·트라이타입을 함께 본다",
    "오늘 일지 한 줄로 남긴다"
  ],
  "limits": "연구·타당성 한계 2~4문장 + 안전 문장",
  "sources": [
    { "label": "…", "url": "https://…" }
  ],
  "centers": {
    "gut": {
      "label": "장 · 본능",
      "types": [8, 9, 1],
      "summary": "한 줄"
    },
    "heart": { "label": "심 · 감정", "types": [2, 3, 4], "summary": "…" },
    "head": { "label": "두 · 사고", "types": [5, 6, 7], "summary": "…" }
  },
  "types": {
    "1": {
      "name": "개혁가",
      "nameEn": "Reformer",
      "center": "gut",
      "summary": "기존 1문장 윤문 가능",
      "coreMotivation": "2~3문장",
      "coreFear": "2~3문장 (경향 표현)",
      "strengths": ["…", "…", "…"],
      "shadow": ["…", "…"],
      "growthQuestions": ["…", "…", "…"],
      "wingHint": "1w9 / 1w2를 볼 때 한 단락",
      "mirrorPractice": "10~30초 실습 1문장"
    }
  }
}
```

### 3.2 필드 작성 규칙

| 필드 | 길이 | 톤 |
|------|------|-----|
| `summary` | 40~70자 | 정의, 단정 금지 |
| `coreMotivation` / `coreFear` | 2~3문장 | 「~하려는 경향」「~이 불편할 수 있음」 |
| `strengths` / `shadow` | 각 2~4개 | 명사구·짧은 절 |
| `growthQuestions` | 2~3개 | 오늘/지금 시제 질문 |
| `wingHint` | 1단락 | 인접 유형 이름만, 점수 확정 해석 금지 |
| `mirrorPractice` | 1문장 | 실행 가능 |

**금지어:** 치유, 운명, 팔자, 반드시, 당신은 ○○형 인간(고정), 진단, 장애, 치료  

**권장 어휘:** 경향, 가설, 스냅샷, 울림, 거울, 기록, 패턴, 오늘  

### 3.3 문항(`items`) 정책

- **기본: 63문항 유지** (스펙·채점 안정)  
- 카피 품질 이슈가 있는 문항만 **개별 윤문** (유형 밸런스 깨지지 않게)  
- 신규 문항 추가는 본 계획 **페이즈 4 이후** 백로그

### 4.2 결과 화면 (우선 구현)

```

  coreMotivation / coreFear

블록 B — 빛과 그림자
  strengths / shadow

블록 C — 날개 · 트라이타입

  mirrorPractice

탐구 일지 (기존)

limits 재노출 (짧게) + disclaimer
다시 하기
```

## 5. 집필 프로세스

### 5.1 유형 1편 워크플로

1. Brain 유형 페이지 + 클리핑 **키워드만** 스케치 (복붙 금지)  
2. 스키마 필드 초안 작성 (별빛 톤)  
3. 금지어·단정 검수  
4. 결과 UI에 넣어 모바일 확인  
5. 파일럿 승인 후 나머지 8유형 동일 템플릿  

### 5.2 집필 순서 (추천)

파일럿: **유형 6(충성가)** 또는 **유형 9(평화)** — 문항 톤·사용 빈도와 맞추기 쉬움.  
이후: 3 → 1 → 2 → 4 → 5 → 7 → 8 → (파일럿 외 나머지).

센터별로 묶어도 됨: heart(2·3·4) → head(5·6·7) → gut(8·9·1).

### 5.3 limits / sources 정본

- 본문: Brain `애니어그램 연구와 한계`의 **현재 판단·한계·안전 문장**을 사이트 톤으로 축약  
- 링크 후보:
  - PubMed/ systematic review (Brain papers에 있는 항목 URL 확인 후)  
  - 사이트 연구 허브  
- 「연구가 있다 = 진단 도구」 논리 금지  

### 5.4 저작권·품질 가드

| 허용 | 금지 |
|------|------|
| 자체 문장 재작성 | Riso/Hudson·Institute 장문 번역 전재 |
| 일반적 유형 라벨(개혁가 등) 통용 명칭 | 타사 검사 문항 복제 |
| 학술 요약 + DOI/URL | 네이버 상담 광고 문구 |
